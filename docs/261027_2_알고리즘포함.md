## 1. GitHub와 로컬 연결 상태

**질문:** 지금 깃허브랑 내 로컬 뮤지컬 프로젝트랑 다 연결돼 있는 거야?

**확인 결과:** 연결돼 있고, 확인 시점에는 로컬과 GitHub이 완전히 같은 상태였습니다.

| 항목 | 상태 |
|---|---|
| 원격 저장소 | `origin` → `https://github.com/2ma1995/pickle-src.git` (비공개 소스 저장소) |
| 원본 폴더 | `OneDrive/새싹/뮤지컬_플젝/pickle-src`, `main` 브랜치가 `origin/main` 추적 |
| 작업 폴더 | `orca/workspaces/pickle-src/PICKLE`, 같은 저장소의 worktree (`soobworks/PICKLE` 브랜치) |
| 권한 | fetch 성공, push는 dry-run으로만 확인 |

참고 사항:
- 원본 저장소가 OneDrive 폴더 안에 있어서, 동기화가 `.git` 파일을 건드리면 충돌이나 잠금 문제가 생길 수 있습니다.
- 사용자 지시: **브랜치를 새로 만들지 말고 원본 파일도 건드리지 말 것.** 이후 작업은 이 지시를 따랐습니다.

## 3. 지금 사이트가 데이터를 쓰는 방식과 시트 연결 방법

사이트는 **구글시트를 직접 읽지 않습니다.**

```
구글시트 탭 ──(TSV로 저장)──▶ data/*.tsv ──(python recommend.py --export)──▶ app/data.js
                                                                              │
                                     app/index.html이 window.PICKLE_DATA로 읽음
                                     사용자 선택은 브라우저 localStorage에 저장
```

- 서버 없이 GitHub Pages(`2ma1995/pickle`, 공개)로 배포하는 정적 사이트입니다.
- `deploy_pages.sh`가 소스 저장소(`pickle-src`, 비공개)에서 화면 파일만 골라 배포합니다.
- 매주 월요일 06시에 GitHub Actions(`weekly-kopis`)가 KOPIS 목록을 새로 받아 자동 배포합니다.
- 화면은 주소의 `#`으로 나뉩니다.
  - `#taste/1~3` 취향 입력
  - `#home` 홈
  - `#show/작품` 작품·회차 추천
  - `#plans` 내 공연
  - `#tag/번호` 관람 기록
  - `#me` 내 취향
- 근거 문장과 출처 링크는 공개 파일인 `data.js`에 넣지 않습니다(10/13 결정).

### 시트 3 연결: 이미 있는 통로 사용
1. 탭을 TSV로 내려받습니다.
2. `data/`의 같은 이름 파일을 교체하거나 `recommend.py`의 파일 경로를 고칩니다.
3. `python recommend.py --export app/data.js --no-track`을 실행합니다.
4. `python -m http.server 8765`로 띄워 `localhost:8765/app/`에서 확인합니다.

### 시트 1 연결: 형식 변환 필요
- 시트 1은 "한 행 = 배우 1명"이고 태그가 한 칸에 여러 개 들어 있습니다.
- 코드는 "한 행 = 배우 1명 × 태그 1개" 모양을 읽습니다.
- 변환할 때 정할 것:
  - 구분자 처리: `,`와 ` / `가 섞여 있음
  - 상태 표준화: 확정/후보/검수 필요/제거로 통일
  - 배우 일반 태그와 이번 배역 태그 분리
  - 조합 태그의 "실제 동회차 확인" 열 보존
- 이후 팀원이 이 변환을 구현했습니다(`data/mvp/evidence_long.tsv`). 후보·검수 필요 태그는 베타용으로 확정 처리했습니다.

## 4. 화면 흐름 문서와 현재 구현 비교

| 흐름 문서 | 현재 사이트 | 할 일 |
|---|---|---|
| 하단 메뉴 홈/내 공연/내 취향 | 이미 같음 | 없음 |
| 신규·기존 사용자 분기 | 신규는 취향 입력으로 보냄(`entryRoute`) | 신규도 홈으로 보내고 블러 카드 표시 |
| 취향 카드 앞뒷면 뒤집기 | 없음 | `V.home`에 새로 만들기 |
| 온보딩 5단계 + 배우 + CSV | `#taste/1~3` (카드 최대 3개 + 음악 최대 2개) | 질문·제외 배우 추가 |
| 작품으로 찾기 | `#show/작품`이 비슷함 | 포스터 그리드·뒤집기 추가 |
| 배우로 찾기 (OR/AND) | 작품 안에서 배우 고르기만 있음 | 새 화면 |
| 내 공연 → 후기 → 카드 갱신 | `#plans`·`#tag`·`personalWeights`로 대부분 있음 | 카드 제목 재계산 |
| CSV 가져오기 | 없음 | P1 새 기능, 브라우저 안에서만 처리 |

화면을 바꾸면 `tests/proto_check.js`도 같이 고쳐야 합니다.

## 5. 작품 추천을 뺄 경우 진행 순서

**사용자 의견:** 데이터는 다 모인 것 같으니 지금 사이트 화면에 구글시트 데이터를 연동하고 화면 구성만 바꾸면 될 것 같다.

**남는 흐름:** 취향 카드 홈 → 배우로 찾기(또는 작품 목록) → 작품 상세·배역별 비교 → 캐스트 조합·회차 추천 → 내 공연 → 후기 → 카드 갱신

"작품 추천을 뺀다"는 흐름 문서의 탐색 경로 A(포스터 그리드, 취향에 맞는 작품 우선 노출)를 뺀다는 뜻으로 정리했습니다. 작품은 골라야 하므로 추천 없는 작품 목록은 남깁니다.

### 확인 당시 빈 곳
- 스위니토드·레베카: 배역·회차 데이터가 없었음 → 8절에서 해결
- 시트 1 태그: 거의 후보·검수 필요였고 상태 문구가 제각각 → 팀원 변환기에서 베타용 확정 처리
- 공식 영상: 시트 1에는 2명뿐 → 로컬 `videos_*.tsv`로 대체

### 순서
- **0단계: 결정**
  - MVP 작품 범위
  - 후보 태그 사용 여부
  - 온보딩 질문 1(작품 분위기) 유지 여부
- **1단계: 데이터 먼저**
  - 시트 3 동기화
  - 시트 1 변환
  - 작품 추가
  - 테스트
- **2단계: 화면 (흐름 문서 P0 순서)**
  - 홈 취향 카드
  - 온보딩 확장
  - 배우로 찾기
  - 카드 갱신
  - CSV는 그다음

## 10. 캐스트 1순위·2순위 추천 알고리즘

### 사용자 문제 제기
> 작품을 선택하면 보고 싶은 배우 1순위, 2순위를 고르게 할 것이다. 같은 배역에서 여러 명을 고르면 1순위 배우를 우선으로 조합을 짜면 된다. 그런데 이용자가 조연까지 세세하게 지정했는데, 1순위 배우와 그 조연들은 맞는 회차가 없고 2순위 배우로는 있다면? 1순위 배우 + (조연 양보)로 줄지, 2순위 배우 + 지정 조연으로 줄지, 이런 경우의 가정과 알고리즘을 세세하게 짜야 할 것 같다.

### 실제 데이터 예시 (스위니토드)
"스위니 토드 1순위 조승우, 2순위 강필석 + 토비아스 황순종, 조안나 장혜린"을 고른 경우:

| 스위니 토드 | 전체 회차 | 황순종+장혜린 함께 |
|---|---|---|
| 조승우 (1순위) | 8 | **0** |
| 강필석 (2순위) | 8 | **0** |
| 김주택 (안 고름) | 7 | 3 (12/5 저녁, 12/18 저녁, 12/20) |

현재 코드(`pinsByRole`·`passes`)는 고른 배우를 전부 반드시 만족해야 하는 조건으로 걸고, 우선순위 개념이 없습니다. 그래서 이 경우 결과가 0개가 됩니다.

### 추천: "순위 사전식 비교 + 양보 카드"

#### 기본 가정
1. **순위는 배역별이 아니라 사람 전체에 매깁니다.** 1순위가 조연일 수도 있으므로 "주연 > 조연" 규칙은 쓰지 않고 사용자가 매긴 순위만 따릅니다.
2. **같은 배역에서 여러 명을 고르면 대체 후보입니다.** 1순위가 안 되면 2순위를 씁니다.
3. **순위 없이 지정한 조연은 맨 뒤의 한 묶음입니다.** 묶음 안에서는 몇 명이 맞는지만 셉니다.
4. **"꼭"(필수)과 "빼기"만 하드 조건입니다.** 나머지는 전부 "가능하면"입니다.

#### 알고리즘
```
0. 후보 = 기간 안 + 공개 판매 회차 (전관·비공개 회차 제외)
1. 하드 필터: 빼기 배우가 나오면 제거, '꼭' 배우가 없으면 제거
2. 회차마다 만족 벡터를 만든다
     v = [1순위 있음?, 2순위 있음?, 3순위 있음?, …, 순위 없는 지정 조연 맞은 수]
3. 사전식 비교: 앞자리부터 비교해서 처음 달라지는 자리에서 큰 쪽이 이긴다
     동점이면 → 취향 태그 점수(지금 pts) → 이른 날짜
4. 같은 캐스트 회차끼리 묶어 조합 카드로 보여준다 (지금 groups 그대로)
5. 1등이 놓친 게 있으면 '양보 카드'를 같이 보여준다
6. 결과가 0이면 뒤에서부터 푼다: 순위 없는 조연 → 낮은 순위 → … ('꼭'은 안 풀고 사용자에게 묻는다)
```

질문한 상황에서는 기본적으로 **1순위 배우 + 조연 양보**가 이깁니다. 1순위 자리에서 이미 앞서기 때문입니다.

근거가 된 설문 결과:
- "보고 싶은 배우를 우선하되 다른 배역도 고려"가 가장 흔한 답이었습니다.
- 회차를 고른 이유 1위는 최애·호감 배우(108건)였습니다.

#### 양보 카드
1등 카드가 사용자가 원한 걸 하나라도 놓쳤다면, **놓친 것을 살리는 최선의 회차**를 함께 보여줍니다.

> **조승우 회차** · 토비아스는 강병훈, 조안나는 장혜린이에요 (황순종 양보)
> ↔ **황순종·장혜린을 모두 원하면** → 김주택 회차 3개 (조승우·강필석 양보)

- 무엇을 포기할지 사용자가 직접 고르게 합니다.
- 흐름 문서의 "추천 근거·선택 조건 표시" 원칙과도 맞습니다.
- 양보 카드는 놓친 항목마다 최대 1~2장만 보여줍니다.

#### 가중치 합산 방식을 피하는 이유
- "1순위 10점, 2순위 5점, 조연 각 3점"처럼 더하면 조연 몇 명이 1순위를 뒤집는 일이 생깁니다.
- 그 경계도 숫자를 어떻게 정하느냐에 따라 달라져서 설명할 수 없습니다.
- 사전식은 "1순위가 되면 1순위부터"라고 한 문장으로 설명됩니다.

#### 정해야 할 것 (추천안)
| 항목 | 추천 |
|---|---|
| 기본 우선 | 배우 순위 우선(사전식). "조합 우선" 토글을 두면 지정 조연 수를 벡터 맨 앞으로 옮기기만 하면 됨 |
| 순위 범위 | 사람 전체 순위 (배역 무관) |
| 조연 순위 | 순위 없이 "가능하면" 묶음, 원하면 "꼭"으로 올림 |
| 고른 기간에 1순위 회차가 없을 때 | 결과는 2순위로 보여주고 "조승우 회차는 12/4~12/19에 있어요" 안내 |
| 회차표가 공개되지 않은 기간 | 추천하지 않고 "캐스팅 미공개"로 표시 |

#### 구현 위치
- `app/index.html`의 `recommend()`
  - 하드 필터(`passes`)를 1~2단계로 바꾸기
  - 정렬 키를 3단계로 바꾸기
  - 양보 카드 계산 추가
- 화면은 배우 선택 순서를 순위로 저장하기만 하면 됩니다.
- 위 스위니토드 예시를 테스트로 추가합니다.
- 온보딩 개편이 `soobworks/PICKLE`에 커밋돼 있으므로, 그 위에서 구현하는 것이 충돌이 적습니다.
