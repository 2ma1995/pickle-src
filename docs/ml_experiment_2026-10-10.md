# 오프라인 ML 실험: 좋아하는 배우 추천을 규칙 대신 데이터로? (2026-10-10)

앱·data.js는 바꾸지 않은 오프라인 실험이다. 재현: `python3 ml_experiment.py` (표준 라이브러리 + numpy).

## 데이터와 방법

- 설문 1차 응답자 259명 중 좋아하는 배우를 적은 사람 238명, 2명 이상 197명, 언급 1140건, 서로 다른 배우 322명.
- 완전히 같은 배우 목록을 낸 응답자는 2명뿐이라 교차검증에서 같은 목록이 훈련·평가로 갈려 성능이 부풀 영향은 거의 없다.
- 쓴 열: 19번(좋아하는 배우 자유 글)과 21~25번(취향 5축). 나이·성별 같은 개인 정보 열은 읽지 않았고, 아래는 전부 집계다.
- 이름 정리: 쉼표·슬래시·점·공백으로 나누고 끝의 배우님·님·씨·등을 떼서 한글 2~4자만 남김, '없습니다·없음' 등은 버림(띄어쓰기 없이 붙여 쓴 이름은 못 가른다).
- 풀: **P1** = 3번 이상 언급된 배우 139명(그중 프로필 있는 배우 49명), **P2** = P1 중 프로필(actorProfiles) 있는 배우 49명. 풀 크기가 작아서 무작위로 맞힐 확률도 높다: hit@5 무작위 ≈ 0.04(P1) / 0.11(P2), hit@10 ≈ 0.07 / 0.22.
- 평가: 좋아하는 배우가 2명 이상인 응답자마다 한 명을 가리고(leave-one-out) 나머지로 가린 배우의 순위를 본다. 이미 적은 나머지 배우는 후보에서 뺀다. 동점은 무작위 순서의 기대값.
- 교차검증: 응답자 단위 5겹 × 3번 반복. 훈련 통계(인기·동시 등장·회귀)는 훈련 응답자만으로 만들어 가린 사람은 훈련에 없다. 하이브리드의 가중치·회귀 규제(람다)·M2 변형은 바깥 훈련 안쪽 4겹으로 고른다. (풀 정의는 전체 언급 수 기준이라 약간 낙관적이다.)
- 신뢰구간·p: 응답자 단위 부트스트랩 2,000번(한 사람의 사례가 여럿이라 사례 단위로 재면 구간이 좁게 나온다). '이김'은 M0 대비 MRR 차이의 95% 구간이 0보다 큰 경우.

## 해석과 앱 적용 권고

**한 줄 결론: 규칙을 ML로 통째로 바꿀 이유는 없고, '같이 좋아하는 배우'(협업 필터링)를 별도 신호로 더하는 건 근거가 있다. 특성 신호(M1·M3)는 혼자서는 인기순을 못 이기지만 협업 필터링 위에 얹으면 조금 보탠다(M4a). 다만 설문이 작고 협업 필터링의 정체가 취향 유사성이 아니라 함께 본 작품(노출)일 수 있어서, 앱에 넣으려면 조건이 붙는다.**

1. **M0 인기순을 이긴 모델** (MRR 기준, 풀 P1 / P2 / P3): M2c P1 이김 / P2 이김 / P3 이김 · M2p P1 이김 / P2 차이 없음 / P3 이김 · M4a P1 이김 / P2 이김 / P3 이김 · M4b P1 이김 / P2 이김 / P3 이김. M1(지금 규칙) P1 짐 / P2 짐 / P3 차이 없음, M1v(목소리만) P1 차이 없음 / P2 차이 없음 / P3 차이 없음, M3(축×태그 회귀) P1 차이 없음 / P2 차이 없음 / P3 차이 없음, M3p(+인기) P1 차이 없음 / P2 차이 없음 / P3 차이 없음.
2. **협업 필터링(M2)이 핵심 신호다.** 인기 상위 10명을 뺀 풀 P3은 인기순이 거의 못 맞히는데(M0 hit@5 0.05) M2c는 hit@5 0.15로 이김이다 → 단순 인기 때문만은 아니다. 하이브리드가 M2c 단독보다 나은지(MRR 차이 구간, P1 / P2 / P3): M4a P1 더 나음 / P2 더 나음 / P3 차이 없음, M4b P1 차이 없음 / P2 차이 없음 / P3 차이 없음. M4a가 P1, P2에서 더 나아서 특성 신호가 협업 필터링 위에 작게 보태진다(P3에서는 차이 없음 → 인기 밖 배우에게는 아직 못 보탠다). 다만 M4b(인기 포함)는 M2c와 구간 안에서 차이가 없다.
3. **지금 규칙(M1: 프로필 특성 유사도)은 '같이 좋아할 배우'를 인기순보다 잘 맞히지 못한다**(M1 P1 짐 / P2 짐 / P3 차이 없음, 목소리만 M1v P1 차이 없음 / P2 차이 없음 / P3 차이 없음). 이 실험은 '좋아하는 배우 목록이 서로 닮았나'를 보는 것이고, 앱의 '닮은 특성의 배우' 목록은 점수·순위를 안 매기는 후보 안내라서 곧바로 틀렸다는 뜻은 아니다. 다만 프로필이 있는 배우는 풀 P1 139명 중 49명뿐이고 배우당 서로 다른 태그가 평균 2.4개라 특성 유사도의 변별력이 약하다. '닮았다'를 예측력이 있는 것처럼 말하지 않는 게 안전하다.
4. **축 답→배우 태그 회귀(M3)가 인기 위에 더하는 것**: M3 P1 차이 없음 / P2 차이 없음 / P3 차이 없음, M3p(+인기) P1 차이 없음 / P2 차이 없음 / P3 차이 없음. 학습한 부호는 앱 규칙이 방향을 말하는 37칸 중 26칸(70%)에서 규칙과 같고, 부호가 안정적인 12칸만 보면 10칸이 같다. 규칙과 반대로 안정적인 칸: 가창↔연기 × 관계 중심(-0.46), 가창↔연기 × 배역 싱크로(-0.24). 대체로 규칙의 방향을 지지하지만 반대인 칸은 규칙의 태그 연결(특히 '연기 중심' 쪽에 묶은 태그)을 다시 볼 후보다. '축 취향→태그' 규칙을 ML로 대체할 근거는 이 데이터에 없다.
5. **앱에 넣는다면 (권고)** — ①이름은 '이 배우를 좋아한 사람들이 같이 좋아한 배우'처럼 *공동 선호* 라벨로 따로 보여 주고, '닮은 특성'과 섞지 않는다. ②응답 원본은 data.js에 넣지 않고, 배우 쌍 집계(둘을 함께 적은 응답자가 최소 3명인 쌍만, 배우당 이웃 5명 이내)만 내보낸다. ③후보 풀이 3번 이상 언급된 배우 몇십~백여 명뿐이라 적용 범위가 좁다. ④설문(238명)이 늘거나 2차 설문(data/survey/survey2_*)으로 다시 평가한다. ⑤점수·순위·'%'는 쓰지 않는다(지금 앱 원칙 그대로).

### 이 실험의 한계

- 정답 = 설문에서 '좋아한다고 적은 배우'. 실제 관람 만족·재관람 같은 결과가 아니고, 취향이 맞아서 같이 적었는지 같은 작품을 봐서 같이 적었는지는 가를 수 없다(협업 필터링이 강한 이유일 수 있다).
- 응답자 238명(2명 이상 197명) 표본이라 구간이 넓고, 풀 정의(3번 이상 언급)는 전체 응답 기준이라 약간 낙관적이다. 사례 하나하나가 독립이 아니라서 응답자 단위 부트스트랩으로 구간을 냈다.
- 이름 파싱이 단순해서(띄어쓰기 없이 붙여 쓴 이름은 버림, 별명·성만 쓴 응답 못 잡음) 일부 응답이 빠졌다. 프로필(actorProfiles)은 배우당 태그가 적고 49명뿐이라 M1·M3에 불리하다.
- 추천 목록의 후보는 '지금 하는 공연에 나오는 배우'로 제한되지만 이 평가는 풀 전체에서 순위를 본다. 실서비스 효과(클릭·예매)는 이 실험으로 알 수 없다.
